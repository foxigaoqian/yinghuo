# 决策记录与待验证事项

## 1. 已有方向

沿用产品V2：萤火品牌、移动优先、小程序可迁移、现代浅暖白磨砂、一页创建且照片可选、普通聊天气泡、单列社区、人物与真实成员分开、文字无次数付费墙、不按分钟计费、先试听再开声音、已存记忆可导出。

本轮用户授权的是形成开发文档并放入GitHub仓库；没有把所有价格、供应商、平台能力或全部52页开发范围当成已确认上线决定。

## 2. 本次架构建议

| 决策 | 理由 | 何时重新考虑 |
|---|---|---|
| uni-app/Vue3为默认候选 | H5与小程序共用工程，已有适用组件 | 双端小样失败或实际研发更熟React时比较Taro |
| NestJS模块化单体 | 一名主要研发维护；交易/权限集中 | 有实际负载或团队边界后再拆服务 |
| PostgreSQL是权威账本 | 订单、权益、版本与关系一致性 | 不因模板习惯随意改为多个数据库 |
| 自建事实库，pgvector按需 | 用户可更正/撤权，权限在自有服务 | 检索评测证明需要更复杂框架 |
| AI用服务端适配器 | 首发避免GPU运维，便于供应商替换 | 实际规模与成本支持自部署时 |
| 先做付费交付和售后，再开声音年费 | 音色相似与持续合成成本未验证 | 达到效果与单位经济门槛后 |

## 3. 对V2未完全定义事项的实施补充

| 事项 | 本稿建议 | 状态/影响 |
|---|---|---|
| 20条记忆与媒体关系 | 20条指确认事实，素材另按容量 | 产品确认后写权益说明 |
| 年费到期有多于20条事实 | 全部仍可读，用户指定20条用于基础对话 | 新增产品细节；不删旧事实 |
| 免费名额被用完 | 新TA为draft，开通后activate；删除不自动恢复免费资格 | 免费资格恢复政策待团队决定 |
| 无TA购买独立作品 | 归购买账号作品空间，可下载，后续转入TA | 保留期限与容量成本开售前定稿 |
| 家庭权限 | owner不能看成员私聊；发布他人素材需另授权 | 强化原权限描述 |
| 影像会员价范围 | 建议购买账号、绑定有效付费TA | 家人是否共享折扣另决策，前端须明示 |
| 原图保留 | 始终保留，不做能销毁原件的开关 | 替换早期“保留原图开关” |
| 留声200汉字 | 建议统一200可见字符，Unicode字素计数 | 需改页面为200字并确认，不静默变更已售规格 |
| 升级剩余价值 | 按秒比例、分四舍五入，UI显示抵扣 | 比原“按天”更精确，条款要同步 |
| 升级退款恢复时长 | 原剩余秒数减升级期间已过时间 | 待团队确认，防双重延长；历史订单按已售版本 |
| 付款后音色尚未激活 | 不消耗新服务天数，旧权益暂保留 | 生成/激活完成再开始365天 |
| 整个TA删除 | 单独强确认、各成员数据影响与导出政策 | 需确定导出窗口再开放不可逆全删 |
| 孤立上传/导出包 | 建议24小时清理/过期 | 仅暂存物，不适用于原始记忆和付费作品 |

这些细化不是绕过价格确认。实现可先配置化或关闭销售，确定后用新商品/条款版本发布，不能影响已付费权益。

页面编号不可随意重排；新增页面从P53开始。修改价格同时更新商品规格、前端价目、交易测试、售后说明；修改权限同时更新数据模型、查询条件、导出与检索用例。修改阶段时更新页面注册表与任务计划。

每次业务规则变化注明“原因、影响范围、已售订单如何处理”，让产品、前端和后端使用同一套定义。
