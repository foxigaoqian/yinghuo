逝者智能体

全站页面文案与交互文案 V1.0

面向 MVP 开发落地 · 首页 / 创建 / 聊天 / 记忆 / 家庭共建 / 账户 / 支付 / 异常状态

核心原则

• 先给价值，再索取信息

• 前台只讲“人、关系、记忆、下一步”，技术词留在后台

• 不假装逝者真实回归；AI 不知道的事情不编造

• 让用户感觉是在慢慢留下一个人，而不是配置一个智能体

版本日期：2026-09-23

# 1. 全站文案策略

这份文档不是品牌口号合集，而是给产品、设计、前端和后端直接使用的“页面级文案规范”。所有文案优先服务于三个目标：降低第一次使用门槛、建立记忆可信感、让用户自然形成长期使用关系。

## 1.1 语气

| 要做到 | 不要变成 |
| --- | --- |
| 克制、温柔、清楚 | 煽情、神秘、故意制造“复活”错觉 |
| 像整理一本家庭相册 | 像配置 AI 模型或知识库 |
| 短句、普通人一眼能懂 | 技术术语、抽象概念、长说明 |
| 明确告诉用户系统知道什么、不知道什么 | 为了“像真人”而补全不存在的事实 |
| 行动导向：下一步是什么 | 只展示状态，没有出口 |

## 1.2 全站统一词汇

| 不要写 | 统一改成 |
| --- | --- |
| 创建智能体 / 新建角色 | 留下一个重要的人 / 记录一个人 |
| Persona / 人设 | TA 的性格与习惯 |
| Memory / Knowledge Base | 关于 TA 的记忆 |
| 训练模型 | 补充关于 TA 的信息 |
| 数据集 | 资料 / 记忆 |
| Voice Clone | 留下 TA 的声音 / AI 模拟熟悉的声音 |
| Digital Resurrection / 数字复活 | AI 记忆陪伴 / 记忆空间 |
| 100% 还原 | 尽可能参考你提供的资料 |
| Prompt | 设置 / 说明 |
| UID | 家庭编号 |
| Account Recovery | 找回我的家庭空间 |

## 1.3 禁用表达

- “TA 真的回来了”
- “让逝者复活”
- “与真实的 TA 再次见面”
- “100% 复刻真人”
- “灵魂永存”
- 任何把 AI 生成内容描述成真实逝者新表达的文案

替代原则：可以表达“记忆被保存”“AI 参考已有资料生成回应”，不能把系统能力写成现实身份延续。

# 3. 首页 / 首次访问

## 3.1 未创建 TA 的首页

> 页面文案 主标题：把你记得的 TA，慢慢留下来 副标题：不需要准备完整资料。从一个名字、一段故事、一张照片开始就好。 主按钮：留下一个重要的人 次按钮：找回之前的记录 信任提示：你留下的内容只属于你的家庭空间。

### 首页下方三项说明

> 三项价值说明 不用先整理资料：想起什么，就慢慢补充什么。 每段记忆都由你确认：AI 不会把猜测自动当成真实经历。 可以和家人一起记录：故事、照片和声音，可以由不同家人慢慢补全。

## 3.2 已有 TA 的回访首页

> 回访态 欢迎语：欢迎回来。 人物卡标题：妈妈 人物卡说明：上次聊到：你明天要去面试。 主按钮：继续聊聊 次入口：看看最近留下的记忆 轻提示：今天想起什么，也可以直接记下来。 说明：欢迎语不要过度拟人化，不要写“妈妈一直在等你”。

# 4. 创建 TA：3 步完成，不做资料大表单

## 4.1 第 1 步：关系

> 页面文案 进度：1 / 3 标题：你想留下谁？ 说明：先告诉我们，TA 是你的谁。 选项：妈妈 / 爸爸 / 爷爷奶奶 / 外公外婆 / 爱人 / 朋友 / 其他 按钮：下一步

## 4.2 第 2 步：称呼

> 页面文案 进度：2 / 3 标题：我们怎么称呼 TA？ 输入框占位：例如：妈妈、王阿姨、老周 辅助说明：不方便填写真名也没关系，用你熟悉的称呼就好。 按钮：下一步

## 4.3 第 3 步：TA 怎么称呼用户

> 页面文案 进度：3 / 3 标题：TA 平时怎么叫你？ 输入框占位：例如：小宝、闺女、阿强…… 辅助说明：不确定可以先跳过，以后随时补充。 主按钮：开始聊聊 次按钮：先跳过

## 4.4 创建完成

> 完成反馈 Toast：已经为你留好这个位置了。 下一步：直接进入聊天页 说明：不要弹“智能体创建成功”。

# 5. 第一次聊天体验

## 5.1 空聊天页不能只放输入框

> 首屏引导 顶部说明：这里的回应会参考你保存的记忆和 TA 的表达方式生成。AI 不会把没有依据的内容当成真实经历。 标题：想从哪里开始？ 快捷问题 1：我有点想 TA 了 快捷问题 2：想说说今天发生的事 快捷问题 3：想记录一件以前的事 快捷问题 4：我不知道说什么 输入框占位：想说什么都可以……

## 5.2 用户选择“我不知道说什么”

> 系统回应 那就从一件很小的事开始吧。 你现在最先想到 TA 的，是什么？

## 5.3 AI 没有这段记忆

> 禁止编造时的标准文案 这件事你还没有留给我。 如果你愿意，可以跟我讲讲当时发生了什么。 说明：这是核心安全体验之一。不要用“我不记得了”，避免让系统假装拥有真实逝者记忆。

## 5.4 用户讲完新故事后

> 记忆发现卡片 标题：刚才你提到了一件值得留下来的事 摘要：“妈妈以前每天晚上都会问我吃饭了吗。” 主按钮：留下这段记忆 次按钮：先不用

## 5.5 保存成功

> Toast 已经替你记下来了。

# 8. 声音

# 11. 主动消息 / 关心方式

## 11.1 触发时机

不要在创建完成时立刻请求开启。建议用户已经聊过数次或保存了若干记忆后，再出现轻提示。

> 首次询问 标题：要不要偶尔收到一声问候？ 说明：系统可以参考你留下的习惯、重要日子和最近聊天，在合适的时候生成一条消息。 选项 1：暂时不用 选项 2：偶尔关心我 选项 3：像以前那样多问问我

## 11.2 安静时间

> 时间设置 标题：什么时候不打扰你？ 默认：22:00 - 08:00 说明：这段时间不会主动发送消息。 按钮：保存

## 11.3 事件型主动消息

优先基于用户近期明确说过的事件。例如昨天说“明天要面试”，第二天可以生成“今天面试怎么样？”；不要机械重复每日固定问候。

# 16. 支付与增值服务

## 16.1 原则

- 先展示可感知的试听/预览，再收费。
- 付款前明确展示价格。
- 付款失败不丢表单和上下文。
- 付费结果必须进入账户资产，刷新后仍存在。

## 16.2 支付页

> 支付确认 标题：生成完整版 说明：你已经试听过效果。支付完成后会生成完整内容，并保存在你的家庭空间。 价格：¥XX 主按钮：确认生成 · ¥XX 次按钮：暂时不用

## 16.3 支付失败

> 失败状态 标题：这次支付没有完成 说明：你刚才填写的内容已经替你保存，不需要重新填写。 主按钮：重新支付 次按钮：稍后再说

## 16.4 支付成功

> 成功状态 标题：已经完成 说明：内容正在生成，完成后会自动保存在这里。 按钮：回到家庭空间

# 17. 加载、网络、刷新与草稿恢复

## 17.1 加载中

> 统一规则 优先使用骨架屏，不要整页只写“加载中……”。 超过 8 秒时才显示文字：“正在准备内容，稍等一下。”

## 17.2 网络断开

> 网络异常 标题：网络好像断了一下 说明：你刚才写的内容已经保存在这里。 按钮：重新连接

## 17.3 草稿恢复

> 刷新 / 切后台回来 Toast：已恢复你刚才写的内容。

## 17.4 发送失败

> 聊天消息失败 状态：这条消息还没有发出去。 按钮：重新发送

# 18. 空状态设计

| 场景 | 不要写 | 建议直接写 |
| --- | --- | --- |

# 19. 权限与隐私提示

## 19.1 上传照片时

> 短提示 照片只用于你的家庭空间和你主动开启的 AI 功能。

## 19.2 上传声音时

> 短提示 请只上传你有权保存和使用的声音。AI 生成内容会明确标注为模拟效果。

## 19.3 家庭共建权限

> 邀请确认 标题：允许 XX 查看哪些内容？ 选项：故事 / 照片 / 声音 / 重要日子 默认：只开放完成本次贡献所需的最小范围。 按钮：发送邀请

# 20. 删除与高风险操作

## 20.1 删除单条记忆

> 确认框 标题：确定不再保留这段记忆？ 说明：删除后将不会再用于后续回应。 主按钮：删除 次按钮：保留

## 20.2 删除整个家庭空间

> 第一次确认 标题：删除关于 TA 的所有记录？ 说明：聊天、记忆、照片、声音和重要日子都将被删除。 主按钮：继续删除 次按钮：保留

> 第二次确认 标题：这是最后一次确认 说明：删除后无法恢复。 确认输入：请输入“永久删除” 主按钮：永久删除 次按钮：取消

# 21. 帮助与反馈

## 21.1 页面结构

> 反馈页 标题：遇到什么问题？ 分类：聊天 / 记忆 / 照片与声音 / 支付 / 账号找回 / 其他 描述占位：把你遇到的情况告诉我们，越具体越容易帮你找到原因。 联系方式：手机号或微信（选填） 主按钮：提交反馈

## 21.2 系统自动附带，不让用户手填

- 家庭编号
- 当前页面 URL
- 发生时间
- 浏览器/设备信息

# 25. 文案验收 Checklist

- 用户第一次打开页面，不注册能否直接开始？
- 每个页面是否只有一个最主要动作？
- 系统已经知道的信息，是否还在让用户重复填写？
- 所有“暂无数据”是否都有下一步？
- 敏感上传行为旁边是否立即解释隐私用途？
- AI 不知道的记忆是否明确不编造？
- 所有付费价格是否在用户投入大量填写成本前可见？
- 支付失败、断网、刷新后是否明确告诉用户数据没丢？
- 是否还出现“智能体、训练、知识库、克隆”等不必要技术词？
- 是否存在“TA 真的回来/100%还原”等误导表达？
- 微信/PWA 引导是否可关闭、不会重复骚扰？
- 换设备后是否有清楚的找回入口？
- 邀请家人是否可以先贡献，再要求注册？

# 26. 最终产品文案定位

> 一句话标准 不是“帮用户创建一个数字逝者”。 而是“让系统尽量不打扰用户，把一个重要的人慢慢留下来”。

所有后续新增页面都应先问：这个页面是在帮助用户留下什么？系统能不能替用户少做一步？如果用户现在没有内容，下一步是什么？如果 AI 不知道，怎样诚实地继续对话？
