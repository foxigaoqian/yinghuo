# H5 首发路线：国内用户、Supabase、Stripe

更新：2026-09-27。此文件记录最新产品选择，优先于 09/10/11/16/17 中关于首发同时接微信直连支付的早期规划；历史接口和备选方案保留作参考。

## 已确认的首发选择

- 移动 H5 优先；不开发小程序支付。付费通道只实现 Stripe Checkout；微信直连 H5/JSAPI 暂不接入。
- 套餐是一次性购买一年使用权，Stripe Checkout `mode=payment`；不使用 `mode=subscription`，不承诺自动续费。标价和结算币种以可用 Stripe 账号的实际能力与商品决策核定，不能仅凭前端展示的 ¥99 推断已可收人民币。
- 国内用户为目标，但可访问、可支付和可稳定使用是三个独立验收项；不能用开发者本地网络或桌面二维码的成功代替国内手机测试。
- 正式后端密钥只放部署平台 Secret，不能进入代码、网页或日志；当前预览不接受真实家庭资料。

## 用户需提供的最小输入

1. 开发完成后提供正式域名及备案状态；仅提供域名和备案状态，不需要提供域名账号密码。
2. 新加坡项目和基础表已创建；下一步配置服务端 Secret、账户找回和真实后端部署。现有悉尼数据库保持原状。
3. Stripe 已有收款账号。还需核对开户国家/地区、结算币种、微信钱包是否在该账号可启用及商品类目；只反馈能力状态，密钥通过部署平台 Secret 配置，不在聊天、GitHub 或截图中传递。
4. 确认正式服务的最小销售规格：年费是否 ¥99、是否只卖一次性年度权益、客户支持邮箱/联系方式及退款口径。尚未确认则展示价格但不开支付按钮。

## 研发任务与上线门禁

- 将访客建档、记忆、对话从临时 KV 切到可恢复的正式账号和数据库；目前正式 NestJS API 的生产模式被 `apps/server/src/config.ts` 明确拒绝，Supabase 模式聊天也没有真实模型。不能靠设置环境变量绕过这些门禁。
- 在服务端实现 Stripe Checkout 创建、webhook 验签、订单幂等、权益生效、支付取消/恢复、退款、对账；前端仅展示服务端可用的收款入口。切换付费供应商不意味着这些业务逻辑可省略。
- 制定用户协议、隐私政策、数据导出/删除和 AI 标识，确定公开广场投稿是否延后，确保真实用户资料不会进入演示库。
- 用中国大陆三网手机分别测 HTTPS 首页、注册/找回、保存与刷新、AI 对话、Stripe 收银台（微信内与微信外）、支付回跳及 webhook 到账；测加载时间和失败率，并保留回滚方案。若选择免费内测，支付测试可延期，但不能把临时 KV 当正式数据层。
