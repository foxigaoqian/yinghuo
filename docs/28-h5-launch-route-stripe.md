# H5 首发路线：国内用户、Supabase、Stripe

更新：2026-09-27。此文件记录最新产品选择，优先于 09/10/11/16/17 中关于首发同时接微信直连支付的早期规划；历史接口和备选方案保留作参考。

## 已确认的首发选择

- 移动 H5 优先；不开发小程序支付。付费通道只实现 Stripe Checkout；微信直连 H5/JSAPI 暂不接入。
- 套餐是一次性购买一年使用权，Stripe Checkout `mode=payment`；不使用 `mode=subscription`，不承诺自动续费。标价和结算币种以可用 Stripe 账号的实际能力与商品决策核定，不能仅凭前端展示的 ¥99 推断已可收人民币。
- 国内用户为目标，但可访问、可支付和可稳定使用是三个独立验收项；不能用开发者本地网络或桌面二维码的成功代替国内手机测试。
- 正式后端密钥只放部署平台 Secret，不能进入代码、网页或日志；当前预览不接受真实家庭资料。

## 经核对的服务边界

| 项目          | 事实与开发决定                                                                                                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Supabase 区域 | 官方托管区域列表截至本次核对没有中国大陆或香港；可选新加坡、东京、首尔等区域。现有项目 `jiidddripchdnbipkumn` 位于悉尼 `ap-southeast-2`。现有项目不能原地换区域；如有迁移需要，另建项目并按已有迁移、数据导出和切换方案处理。新项目或供应商费用应先核对。             |
| Stripe 开户   | Stripe 支持地区列表有香港等地区，无中国大陆。必须使用实际可开户且已通过审核的 Stripe 收款账号，并核实银行账户、结算币种、产品类目与 WeChat Pay 是否在该账号可用；不假设“中国用户能付”就等于大陆主体能收。                                                             |
| Stripe 钱包   | 受支持的 Stripe 账号可按官方条件申请/启用 WeChat Pay；Checkout 一次性支付支持该钱包，订阅模式不支持。移动端、微信内、微信外的实际收银体验必须单独验收。Stripe 微信钱包不是微信商户号直连支付，也不保证每个浏览器都能无跳转完成付款。                                  |
| Cloudflare    | 现有 `pages.dev` 是全球 Pages 演示地址；Cloudflare 官方说明 Pages 不在其中国网络内直接提供。绑定自有域名和实测国内访问是上线任务，不可宣称 Pages 在中国大陆本地托管或保证所有网络可访问。Cloudflare 中国网络另有 Enterprise/独立订阅及 ICP 要求，不作为首发默认方案。 |
| 数据合规      | 对境内用户个人信息采用海外存储/处理时，需核实数据流向及适用的告知、单独同意等义务；选更近的海外机房不会自动满足境内存储要求。                                                                                                                                         |

## 用户需提供的最小输入

1. 一个要绑定的正式域名，以及它是否已经备案；仅提供域名和备案状态，不需要提供域名账号密码。
2. 决定继续使用现有悉尼 Supabase，或新建新加坡/东京项目，或选择境内替代数据库。只有选择确定之后才改生产连接；不直接改动现有数据库。
3. 若要收费：确认**已有可正式收款的 Stripe 账号**的开户国家/地区，在 Stripe Dashboard 的 Payment methods 页查看 WeChat Pay 是否可开启，并确认结算账户及商品类目通过审核。只反馈地区与能力状态，API Secret 通过部署平台 Secret 配置，不在聊天、GitHub 或截图中传递。
4. 确认正式服务的最小销售规格：年费是否 ¥99、是否只卖一次性年度权益、客户支持邮箱/联系方式及退款口径。尚未确认则展示价格但不开支付按钮。

## 研发任务与上线门禁

- 将访客建档、记忆、对话从临时 KV 切到可恢复的正式账号和数据库；目前正式 NestJS API 的生产模式被 `apps/server/src/config.ts` 明确拒绝，Supabase 模式聊天也没有真实模型。不能靠设置环境变量绕过这些门禁。
- 在服务端实现 Stripe Checkout 创建、webhook 验签、订单幂等、权益生效、支付取消/恢复、退款、对账；前端仅展示服务端可用的收款入口。切换付费供应商不意味着这些业务逻辑可省略。
- 制定用户协议、隐私政策、数据导出/删除和 AI 标识，确定公开广场投稿是否延后，确保真实用户资料不会进入演示库。
- 用中国大陆三网手机分别测 HTTPS 首页、注册/找回、保存与刷新、AI 对话、Stripe 收银台（微信内与微信外）、支付回跳及 webhook 到账；测加载时间和失败率，并保留回滚方案。若选择免费内测，支付测试可延期，但不能把临时 KV 当正式数据层。
