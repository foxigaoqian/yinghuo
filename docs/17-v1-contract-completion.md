# V1.1首发实施基线与规则冻结

2026-09-19。目标是把已认可产品变成一致的开发输入；不扩大到小程序。没有真实应用/支付/模型验收结果，本稿不宣称已可上线。

## 1. 交付范围与权威文件

A：登录、TA、文字/照片/原音记忆、个人文字聊天、历史、偏好、帮助、授权、导出删除。B：成员协作、价格、订单、一个合格影像工具、作品、支付、退款、相关后台。C1声音、C2用户社区、D更多影像/提醒在独立验收前保持关闭。

P33在A/B仅展示授权运营内容，通过GET /home的publicStories返回；不调用C2帖子/收藏接口。52页是长期目录，不把52页全部称为首发完成。

## 2. 可编码的开发默认规则

以下用于开发环境与内测，正式价格、退款及留存由发布负责人签署商品/条款版本；在签署前saleEnabled=false。规则已售后不可追溯改变。

| 事项 | V1开发默认 | 发布前条件 |
|---|---|---|
| 记忆年费 | 9900分，365天，1TA，5GB，最多5人含owner；手动续费 | 确认商品版本与实际成本 |
| 免费资格 | 每账号终身领取一次；删除不自动恢复；误删申诉由客服审查 | 价格页写清，补偿有审计 |
| 20条记忆 | 确认且activeForBasic的事实条目；媒体按容量另计 | 选择接口原子限制20条 |
| 到期访问 | 旧资料仍可查看和导出，超额禁止新增；基础对话只用已选20条 | 服务成本/留存规则正式承诺 |
| 会员影像折扣 | 购买账号+绑定的有效会员TA；协作者不继承折扣 | 报价/价格页统一 |
| 家庭角色 | 唯一owner，editor可写家庭记忆，viewer只读；个人私聊各自独立 | 所有共享访问测权限矩阵 |
| 成员移除 | 立即禁止该TA访问；个人贡献处理按删除请求流程，不泄露他人记录 | 冲突申诉可追踪 |
| 订单时限 | 报价10分钟；订单默认30分钟，外部Session返回时同步期限 | 渠道关闭确认前不释放交易占用 |
| 独立作品 | 不强制建TA；可下载/后续保存TA；删除由用户主动请求 | 真实保存期限未签署前不售独立作品 |
| 自动退款 | 确定未交付的最终失败创建全额退款请求，不靠前端超时判断 | 财务权限和通道结果核验 |
| 用户不满意 | 支持工单、返工或人工审核退款；不写一律不退 | 明确正式售后文本 |
| 清空聊天 | epoch+1，取消旧生成；只清本人对话 | 在途任务不能写回复活 |
| 删除TA | 仅owner发起，说明所有成员影响；先撤访问，异步删除 | 导出选择与正式保留规则已配置 |
| 导出包 | 创建与下载双重验权，默认24小时有效 | 临时包过期不删除原始数据 |

不开放升级/留声抵扣/续费自动扣款销售；现有高级算法保留C1实施说明。B手动续费同档套餐延长365天。发起退款并冻结未消费交付不等于撤销所有既有权益；实际退款成功后按对应grant归属冲正。

## 3. 会话、幂等与版本

H5 Cookie必须HttpOnly/Secure，GET bootstrap可提供CSRF token；受保护写请求需同源Origin/CSRF校验。根级security=sessionCookie；公共内容、OTP、OAuth回调和渠道Webhook显式例外；后台使用独立adminCookie且MFA会话。

变更共享记录传请求体expectedVersion，不再使用可选expectedVersion header。删除无法携带对象正文时使用required If-Match header（十进制版本）。竞争失败409保留用户草稿。每个事务提交同时增加version；权限检查发生在版本检查前，防泄露对象存在性。

受保护POST/PUT/PATCH/DELETE需Idempotency-Key（OAuth回调/Webhook使用各自协议键）。同(actor,operation,key)相同canonical request hash重放原结果；不同体409；处理中返回409 IDEMPOTENCY_IN_PROGRESS及Retry-After。敏感响应仅存资源ID和状态并重新验权，不把旧私有下载URL永久缓存。24小时后清理请求缓存，支付和交付的业务唯一约束继续有效。

数据库时间为UTC，时限由服务端计算。金额统一非负整数分；JSON只有camelCase，数据库snake_case。返回data/traceId；列表items/nextCursor。对私有对象越权统一404，公共已知能力不足403，未开通渠道422 CHANNEL_UNAVAILABLE。

## 4. 页面状态和跨层追踪

research/v1-traceability.json由检查脚本生成，列明每个A/B页面的operationId、实际路径、阶段；P33另标运营简版。开发PR必须引用页面ID、接口operationId、迁移号、20中的验收ID。

每页有加载、空、失败、就绪；提交中防重复，刷新恢复任务/订单，登录中断保留当前用户草稿，切账号清理。B购买按钮必须先检查商品+通道可售；渠道未开不展示可支付假入口。网络失败提示重试，处理时间只展示后端真实状态，不做假进度。

## 5. 开工与开售不同门槛

开工：契约检查通过、可运行迁移、虚构种子、mock模式、核心页面交互就能启动。开售：收款资格、实际支付退款、模型样片、成本、正式条款、恢复演练全部通过。未知供应商和账号资格不靠文档猜测填满；登记责任人/截止阶段，不能伪造已完成状态。
